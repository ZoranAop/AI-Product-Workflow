# Product Workflow Rules

## Overall Flow

Raw Input → Product Understanding & Planning → Requirement Pool → Single Requirement Definition → Prototype & Dual PRD → Version Commitment → Development & Sync → Acceptance → Launch Verification → Retrospective / Feedback

## Key Disciplines

1. Register raw inputs before using them as formal requirements.
2. After a stage produces a clear conclusion, obtain human confirmation before writing it into permanent project files.
3. One requirement should be able to go through definition, review, development, and acceptance independently.
4. Every important decision must be written back with its background (when, who, why), not only the final result.
5. Keep the Agent's view of the project current; stale context makes even strong models useless.
